# Expansion plan — from EditApart to an NLE-shaped editor

*Companion to [`state-of-the-art-2026-09.md`](state-of-the-art-2026-09.md). This is a
roadmap for THIS repository, not a separate product: each section says what changes
here, and why the change is worth making given what the field already ships.*

**Thesis.** Take the one thing EditApart has that the shipping NLEs do not — an edit
decision that is simultaneously the render input, the critique target and a *trainable*
object with a per-creator latent — and give it an NLE's body: an OTIO-shaped timeline,
draft/approval sessions, a reviewable decision table, and traceable execution.

**What changes vs EditApart.** Its interlingua is a bespoke `structure[]` of segments;
here the interlingua is an OTIO-aligned timeline. Its loop logs candidate groups and
trains a selector; here the same learning happens over *timeline* decisions, with credit
localised to semantic segments. Its surface is a tool loop inside an agent session; here
there is also a human surface (the decision table, the draft diff, the approval gate).

---

## 1. Invariants kept from EditApart (with the reason each one is non-negotiable)

| Invariant | Why it survives the redesign |
| --- | --- |
| **One decision object** is render input + critique target + training datum | It is the property that makes the loop coherent; splitting it recreates the "AI intent vs the render" gap EditApart exists to remove |
| **Deterministic render** | The reward must be reproducible from (timeline, inventory, rubric); a stochastic renderer makes every measurement unfalsifiable |
| **Objective critic + graded reward** (full credit inside tolerance, linear falloff outside) | A graded reward stops a quantised one from tying whole groups (measured in EditApart: 6 candidates all at −0.05 ⇒ zero group-relative signal); an objective critic can be recomputed by a third party |
| **Candidate *groups* generated by the system, logged** | The comparison set must be auditable; a model that chooses its own alternatives can hide the choice (this is also GRPB's core move) |
| **Per-creator latent `z_u` against a frozen shared trunk, with a trunk digest** | ~1 KB identity, composable, and it *refuses* to score against a trunk it was not trained on |
| **The trained policy is a selector, not a fine-tuned LLM** | Keeps the system operable without a training cluster, and keeps the claim honest |
| **Measurement discipline**: pre-registered probes, no-taste control, published corrections | EditTogether's corrections log exists because three conclusions flipped after defects were found — a design that cannot survive that has no business shipping |

## 2. Adopted from the field (with attribution)

| Adoption | Source | Rule we take |
| --- | --- | --- |
| **OTIO-aligned interlingua + declared extensions** | [cutible](https://github.com/plokdalberb-byte/cutible), Timeline Studio's FCPXML export, verified in §2 of the survey | Align timing/structure to the standard; declare extensions explicitly instead of inventing a private format |
| **Draft session → review → atomic apply**, `manual`\|`auto` | [OpenChatCut](https://github.com/0xsline/OpenChatCut) | An agent never mutates the live timeline; a draft is isolated, reviewable, and applied as **one undo step**. Only draft-safe tools are exposed inside a session — a rejected proposal cannot roll back a generation or an export |
| **Versioned operation registry**: validate-only, dry-run, **idempotent operation ids**, predicted diff | [Timeline Studio](https://github.com/MartinDelophy/ai-video-editor) | Every write is an operation with an id; the same plan applied twice is a no-op; a caller can ask "what would change?" before anything changes |
| **Decision table as a projection**, one row per *shot* | [Nomi's decision-table research](https://github.com/aqm857886159/Nomi/blob/main/docs/research/2026-09-07-edit-decision-table-for-agent.md) | One owner (the operation list); the table is derived **from the kernel's executed result**, never assembled from operation JSON |
| **Artifact-first execution** | [Crayotter v1](https://arxiv.org/abs/2606.07636) | Retrieval reports, analyses, blueprints, tool calls, intermediate renders are first-class artifacts so a long edit can be inspected, resumed and repaired |
| **Group-relative preference with segment-local credit + a lag guard** | [Crayotter GRPB](https://arxiv.org/abs/2608.02694) | Zero-sum advantages among same-task alternatives; credit attributed to semantic segments (shot/beat), not one scalar per clip; a group's own judgment must not shape that group's update |
| **Taste is a behavioural prior, never evidence; visible and revocable** | [ReelBrain](https://github.com/Q00/ReelBrain) | The taste model may order candidates and must never be cited as a fact about the footage; the creator can inspect, edit, disable or delete it; explicit current steering beats stored taste |

## 3. Architecture

```
        agent surface (MCP / DSH tools)          human surface (table + diff + review)
                    │                                          │
                    └──────────────┬───────────────────────────┘
                                   ▼
                         session layer  ── draft workspace, approval modes,
                                           one atomic undo step per apply
                                   │
                     operation registry (versioned, idempotent, dry-run,
                       predicted diff, validate-only)
                                   │
                     ┌─────────────┴──────────────┐
                     ▼                            ▼
              timeline core                 decision table (projection)
              (OTIO-aligned,                one row per shot, derived from the
               content-hashed)               kernel's executed result
                     │
        ┌────────────┼─────────────┬──────────────────┐
        ▼            ▼             ▼                  ▼
   deterministic  objective     semantic index    OTIO bridge
   renderer       critic        (shots, beats,    (import/export, external
   (FFmpeg)       + graded      transcript,       finishing in DaVinci/Premiere)
                  reward        region stats)
                     │
                     ▼
              taste model  ── per-creator z_u over a frozen, digest-verified trunk
              (learns from logged candidate groups; selects, never renders)
                     │
                     ▼
              artifact store (every stage's output, inspectable and resumable)
```

## 4. Data model

**Timeline** — OTIO-aligned, with three declared extensions in an `editapart` metadata
namespace (all verified to round-trip, §2 of the survey):

| Need | OTIO-native? | Representation |
| --- | --- | --- |
| Shot, trim, source window | yes | `Clip.source_range` (`TimeRange` over `RationalTime` — rational, not float) |
| Transition | partly | `Transition` with `transition_type`; our vocabulary maps to `Custom` + metadata; **`in_offset`/`out_offset` replace EditApart's single `durationFrames`** (strictly more expressive, and it records a choice we used to leave implicit) |
| Explicit hard cut vs unspecified | no | `custom_metadata.editapart.transition = "cut"` — kept deliberate, so an agent cannot claim every boundary was a designed cut |
| Audio gain / fade / mute | **no** | `Effect(name="AudioFader")` + `metadata.editapart.{gainDb,fadeInFrames,fadeOutFrames,muted}` (the ecosystem precedent) |
| Beats, emotion, markers | yes | `Marker` with `marked_range` (zero-length for a beat), `color` for strong/weak, `metadata` for bpm/role |
| Captions / titles | no | a text track (`Clip` + our text metadata), aligned to Remotion's `Caption{startMs,endMs,timestampMs}` shape so a renderer can consume it |
| Static image as a shot | no | `Track.Kind` has no image kind: declared extension, exported into the Video track |

Two deliberate divergences, recorded as such rather than hidden: we keep **no
`global_start_time`** (a local-first project has no broadcast timecode origin), and we
carry a **content hash** of the timeline so a reward can be tied to an exact revision.

## 5. Sessions: how an agent is allowed to change the timeline

1. `begin_session(mode = manual|auto)` → returns a session id and an isolated draft.
2. Every write inside the session is an **operation** (`op_id`, idempotent, versioned
   against the base revision). `dry_run` returns the **predicted diff** without applying.
3. `review_session` → a reviewable artefact: the diff (three colours: removed / added /
   changed), the projected decision table, and the render of the draft.
4. `manual`: the creator approves in the UI, and **the whole draft applies as one undo
   step**. `auto`: `review_session` applies immediately — but a stale session errors
   instead of silently falling back to manual.
5. Only draft-safe tools exist inside a session. Generation, export, deletion and other
   irreversible side effects are unavailable there, because a rejected proposal cannot
   undo them (OpenChatCut's rule, adopted verbatim).

## 6. The decision table (the surface nobody ships)

**Rule (from Nomi, adopted):** the table is a **projection** of the operation list, and
it is derived from the kernel's *executed result* on the draft — never assembled from
operation JSON. The documented failure mode of the other approach: operations like
`trim`/`transition`/`text edit`/`audio` carry no geometry, so a JSON-derived overlay
silently draws at frame 0 and tells the user something untrue.

**One row per shot** (not per operation), because a row per operation cannot be scanned
for rhythm — the same reason EditApart's group log is per-clip, not per-tweak.

| Column | Source | Note |
| --- | --- | --- |
| shot #, clip id | derived, ordered by start | stable across revisions |
| in / out / duration | executed result | duration is derived, never stored (no second truth) |
| source window | `source_range` | — |
| transition in/out | executed result | type + duration + **alignment** (start/center/end — currently implied, now recorded) |
| captions | executed result | text, in/out, position, style |
| audio | effect metadata | gain dB, fades, muted |
| **beat / emotion** | markers | the one column that spans shots; rendered with a colour scale so a row's role is visible when scanning |
| why | operation rationale | the field that turns a list of actions into a record of *judgement* |

## 6b. What the training datum is, and what must be retained

A datum is a **group** — alternatives under one fixed request/materials/constraint set —
never a timeline plus a scalar. Implemented in the current engine as dataset schema v3
(README, "The training datum"), designed here for the NLE case:

- **Structure** lives in the timeline (OTIO's own container when canonical:
  `otio_json`/`otiod`/`otioz`), because adapters strip — measured, FCPXML writes none of
  our effects, markers or metadata.
- **Judgment** (`why`, decisions, provenance, rewards) lives in the **ledger**, keyed by
  the timeline's content hash. It must not depend on surviving a round trip.
- **Evidence** (the inventory: per-shot motion/luma/rms) and the **constraints** (the
  rubric) travel with the group, because they are what the features and the reward are
  computed from.
- **Raws** are identified by content hash with their available range, so a re-score can
  tell "same source" from "different source" — and three rules follow: media garbage
  collection must be training-aware (never prune a source a logged group references),
  a reward is recomputed only after hash verification (else the group is marked
  non-recomputable), and a render is a disposable cache, never the record.

The acceptance test for all of it is `replay`: re-derive a group from its own record and
compare. A pipeline that cannot replay cannot re-measure, and this project's corrections
log is a history of needing to re-measure.

## 7. The taste layer over a timeline

**Status: the effect half of this section is IMPLEMENTED (2026-09), and per-effect
credit is implemented as an ATTRIBUTION TABLE plus a corpus-wide effect profile
(`edit_apart_core.py attribute`) whose rows are keyed by shot and whose axis comes from
the logged knobs, with `attributable` false for any group that varied several decisions
or changed its material.** The remaining piece is gradient-level: distributing a group's
advantage over the table's rows instead of broadcasting it over the candidate. ** `video/v2` adds
the effect-parameter features and `propose_schema(refine=N)` lets an effect-aware
identity choose those parameters by deterministic coordinate ascent — see the README's
"Multi-input effects" section for what is measured and what is still missing
(per-effect credit attribution, continuous axes, per-effect provenance). The
cross-shot features below remain designed-but-not-implemented.

**Features.** Extends EditApart's `video/v1` layout with cross-shot structure that a
timeline finally makes expressible: cut rhythm and its variance, shot-length
distribution, beat alignment (are cuts on the beat, and which beat), transition usage,
tempo against the rubric's pace, and the existing per-shot luminance/motion/audio
statistics. Same contract as today: a named, versioned feature spec, `to_vector()`, and
a per-creator latent.

**Groups.** A logged group is a set of candidate *timelines* produced by a deterministic
candidate grammar over the operation space (trim/order/transition/pacing/beat-lock),
which keeps the comparison set auditable and reproducible.

**Learning.** Per-creator `z_u` (AdamW) over a frozen shared trunk (Muon on 2D weights),
group-relative advantages among the group's candidates, with two additions from GRPB:
- **segment-local credit** — advantages are attributed to the semantic segments a
  candidate changed (shots, beats), not broadcast over the whole timeline;
- **a lag guard** — a group's own judgment never shapes that group's update (the
  allocator lags by one group), so a bad critic pass cannot bootstrap itself.

**Governance.** The taste model orders candidates; it is never evidence about the
content. It is inspectable (which choices it preferred and by how much), editable,
disableable, and deletable — and explicit current steering always wins.

## 8. Rendering, critique, and what stays honest

- Render is deterministic FFmpeg over the timeline; the same revision renders to the
  same frames.
- The **objective critic** (arithmetic over the timeline and the inventory) produces the
  graded reward the model trains on. The **VLM leg** produces judgement the loop can act
  on but does *not* train on, and its disagreement is logged rather than averaged away —
  EditTogether already measured that a motion/luma heuristic confidently called the two
  best beats "dead air".
- Every claim about the taste model ships with its control: a no-taste identity, and an
  unrelated-picks null, reported beside the effect size.

## 9. Non-goals (kept explicit)

Not a video generator; not a fine-tuned language model; not a cloud service; not a
replacement for a finishing NLE (OTIO export is how a human finishes in DaVinci or
Premiere, and what is *lost* on export is marked rather than implied). The taste model
does not choose goals, write scripts, or decide what the footage means.

## 10. First slices — pick one

| Slice | Content | Why |
| --- | --- | --- |
| **A. Timeline core + OTIO bridge (recommended)** | `timeline/` (OTIO-aligned model + content hash), `otio/` (import/export + extension mapping), the **decision-table projection** + predicted-diff, and `tools/otio_conformance.py` in CI. Pure data + pure functions, host-agnostic | It is the invariant every other slice needs, it is testable today, and it makes the interlingua decision reversible if OTIO proves insufficient |
| B. Taste layer over timelines | Reuse EditApart's `taste_model.py` with the extended feature spec, candidate grammar, segment-local credit + lag guard, and the same measured-claims discipline | Highest research value; needs A's data model to be meaningful |
| C. Session/agent surface | Operation registry (idempotent, dry-run, predicted diff), draft/approval session protocol, MCP/DSH tool surface | Makes it usable from an agent; needs A first |

Recommendation: **A, then B**, with C as the moment a human surface is wanted. A is
small enough to finish and verify in one pass, and it is the only slice whose
*correctness* can be settled against an external standard rather than against ourselves.
